# P14359 题解逐行讲解（值域哈希 + lst 下界法）

## 一、原题解代码

```cpp
#include<bits/stdc++.h>
using namespace std;
typedef long long ll;
const int N = 5e5 + 10;
ll n, k;
ll a[N], s[N];
ll id[2005000], lst;
int main(){
    ios::sync_with_stdio(false);
    cin.tie(0);
    cin >> n >> k;
    for(int i = 1; i <= n; i++) cin >> a[i], s[i] = s[i-1] ^ a[i];
    memset(id, -1, sizeof id);
    id[0] = 0;
    ll ans = 0;
    for(int r = 1; r <= n; r++){
        ll x = s[r] ^ k;
        if(id[x] >= lst){
            ans++;
            lst = r;
        }
        id[s[r]] = r;
    }
    cout << ans;
    return 0;
}
```

---

## 二、变量含义逐个说清

| 变量 | 含义 |
| --- | --- |
| `a[i]` | 原序列第 `i` 个数 |
| `s[i]` | 前缀异或 `p[i] = a[1] xor ... xor a[i]`，`s[0] = 0` |
| `id[v]` | **值 `v` 最近一次出现的下标 `t`**，即最小的 `r` 使得 `s[r] = v` 并不断刷新为最新 |
| `lst` | 上一个被选中区间的右端点；也是「下一个区间左前缀下标的搜索下界」 |
| `x = s[r] ^ k` | 想让 `[t+1, r]` 权值为 `k`，需要 `s[t] = s[r] ^ k` |

核心恒等式仍然是：

```
xor(a[t+1..r]) = s[r] xor s[t]
```

所以要凑出权值 `k`，就是找 `s[t] = s[r] xor k`，也就是看 `id[x]` 是否存在。

---

## 三、`lst` 与判断条件 `id[x] >= lst`

选中的区间必须**互不相交**：

- 设上一个选中区间结束于 `lst`；
- 下一个区间 `[t+1, r]` 要落在它右边，必须 `t + 1 > lst`，即 **`t >= lst`**。

因此条件写成一个不等式即可：

```cpp
if (id[x] >= lst)     // 窗口 [lst, r-1] 中存在 t 使 s[t] = x
```

**为什么「最近一次出现位置」够用？**
我们只需要判断「`[lst, r-1]` 内是否存在 `t` 使 `s[t] = x`」。

- 若 `id[x] >= lst`：取 `t = id[x]` 即可，且 `t <= r-1`（因为 `id[s[r]] = r` 是在判断之后才更新的），合法。
- 若 `id[x] < lst`：`id[x]` 已是 `x` 出现的**最大下标**，它都 `< lst`，说明更早的也全 `< lst`，窗口内不存在，否决。

这就是「最近位置」一次比较就同时完成**存在性判定**和**过期过滤**的巧妙之处。

---

## 四、为什么不需要清空 `id`（与集合版对比）

集合版做法（我们之前讲的）：

```
S = { s[t] : t in [lst, r-1] }    // 命中就 clear 再 insert(s[r])
```

数组版做法：

```
id[v] = 该值最后一次出现的位置     // 从不删除，靠 lst 下界过滤
```

两者**完全等价**：`id[x] >= lst` ⟺ 「`x` 落在当前窗口 `[lst, r-1]` 中」。
区别只是：集合版靠 `clear()` 显式丢弃旧数据，数组版靠 `lst` 这个移动下界**逻辑上**屏蔽旧数据，省掉了清空开销，也更简洁。

## 五、手推验证：`a = [1, 2, 1, 3]`，`k = 2`

前缀异或 `s = [0, 1, 3, 2, 1]`；初始 `id` 全 `-1`，`id[0] = 0`，`lst = 0`。

| r | s[r] | x = s[r]^k | id[x] | id[x] >= lst | ans | lst | 更新 id |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | 1 | 3 | -1 | 否 | 0 | 0 | id[1] = 1 |
| 2 | 3 | 1 | 1 | 1 >= 0 是 | 1 | 2 | id[3] = 2 |
| 3 | 2 | 0 | 0 | 0 >= 2 否 | 1 | 2 | id[2] = 3 |
| 4 | 1 | 3 | 2 | 2 >= 2 是 | 2 | 4 | id[1] = 4 |

- 第 2 步命中 `id[1] = 1` → 区间 `[2, 2]`；
- 第 4 步命中 `id[3] = 2` → 区间 `[3, 4]`。

答案 **2**，与题面最优解一致。旧代码（限定 `l = i`）在这里只会输出 1。

## 六、思路总览

```mermaid
flowchart TD
    A[读入 n k 并求前缀异或 s] --> B[id 全部置 -1 再令 id[0] 等于 0 lst 置 0]
    B --> C[遍历 r 从 1 到 n]
    C --> D[计算 x 等于 s_r 异或 k]
    D --> E{id 中 x 的位置大于等于 lst}
    E -->|是| F[ans 加 1 并令 lst 等于 r]
    E -->|否| G[不做处理]
    F --> H[令 id 中 s_r 的位置等于 r]
    G --> H
    H --> I{是否遍历完}
    I -->|否| C
    I -->|是| J[输出 ans]
```

## 七、这份题解的三个风险点

1. **`id` 数组大小依赖值域**：`ll id[2005000]` 只在「所有 `s[r]` 与 `k` 都小于约 2 * 10^6」时安全。
   若题目的 `a[i]` 或 `k` 可能更大（例如到 `10^9`），`x = s[r] ^ k` 会越界，
   轻则 RE，重则算出错误位置。**务必先确认数据范围**。
2. **`memset(id, -1, sizeof id)`**：对 `long long` 逐字节填 `0xFF` 得到 `-1`，是正确的；
   但要注意随后必须补上 `id[0] = 0`，否则「从第 1 个元素开始的区间」永远查不到，答案会偏小。
3. **输出没有换行**：一般不影响判题，但习惯上加 `'\n'` 更稳。

## 八、值域安全版（推荐写法）

把定长数组换成哈希表，思路完全不变，且不依赖值域：

```cpp
#include <bits/stdc++.h>
using namespace std;
typedef long long ll;

int main () {
    ios::sync_with_stdio (false);
    cin.tie (0);
    int n; ll k;
    cin >> n >> k;

    unordered_map<ll, ll> id;   // 值 -> 最近一次出现的下标
    id.reserve (n * 2 + 10);
    id[0] = 0;                  // 前缀 p[0] = 0

    ll p = 0, lst = 0, ans = 0;
    for (int r = 1; r <= n; ++ r) {
        ll x; cin >> x;
        p ^= x;                              // p 即 s[r]
        auto it = id.find (p ^ k);
        if (it != id.end () && it->second >= lst) {
            ++ ans;
            lst = r;                          // 新区间下界更新
        }
        id[p] = r;                            // 记录最近位置
    }
    cout << ans << '\n';
    return 0;
}
```

三个版本一句话对比：

- **集合版**：`S` 存当前窗口内的值，命中即清空重建 —— 直观，但要 `clear`。
- **数组哈希版**：`id` 存值的最近位置，靠 `lst` 过滤 —— 常数小，但受值域限制。
- **哈希表版**：`id` 同数组版思路，用 `unordered_map` 替代定长数组 —— 通用，无越界风险。
