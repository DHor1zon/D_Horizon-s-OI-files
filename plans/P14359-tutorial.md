# P14359 教学讲义：前缀异或 + 区间调度贪心

## 0. 一句话思路

**前缀异或**把"区间之和"变成"两点之差"，再用**区间调度贪心**（每次选最早结束的区间）求最大不相交区间数量，最后用**哈希集合**把判定优化到 O(n)。

---

## 1. 为什么想到"前缀异或"

题目要判断"某个区间的异或和是否等于 k"。如果每次都去把区间里的数异或一遍，代价太高。
观察异或的性质：异或和加法很像，满足

```
a[l] xor a[l+1] xor ... xor a[r]
= (a[1] xor ... xor a[r]) xor (a[1] xor ... xor a[l-1])
```

这是因为同一段 `a[1..l-1]` 被异或了两次，`x xor x = 0` 抵消掉了。

于是定义**前缀异或**：

```
p[0] = 0
p[i] = a[1] xor a[2] xor ... xor a[i]
```

立刻得到核心恒等式：

```
xor(a[l..r]) = p[r] xor p[l-1]
```

**好处**：任意区间的异或值，只需要两个前缀值相异或，O(1) 就能算出来，不用再遍历区间。

---

## 2. 把题目重新翻译一遍

原来的条件「区间 `[l, r]` 的权值为 `k`」等价于：

```
p[r] xor p[l-1] = k
```

两边同时异或 `p[r]`（异或的逆运算还是异或），得到更好用的形式：

```
p[l-1] = p[r] xor k
```

意思是：**给定右端点 `r`，我去找前面有没有一个前缀位置 `t = l-1`，满足 `p[t] = p[r] xor k`。**

所以问题变成：

> 在 `p[0], p[1], ..., p[n]` 中，尽量多地选出成对的下标 `(t, r)`，满足
> `t < r` 且 `p[t] = p[r] xor k`，并且这些对**不重叠**。

「不重叠」在这里即：若上一对是 `(t1, r1)`，下一对是 `(t2, r2)`，需要 `r1 < t2`（对应原题区间 `[t1+1, r1]` 与 `[t2+1, r2]` 不相交）。

---

## 3. 经典模型：区间调度

这是一个非常经典的模型：

> 有一堆区间，选出**尽可能多**的**互不重叠**的区间。

**结论**：按**右端点从小到大**贪心，能放就放，得到的就是最优解。

**为什么对？——交换论证法**

设最优解里右端点最小的区间是 `I`，贪心第一个选的是 `G`。
因为贪心选的是右端点最小的合法区间，所以 `G` 的右端点 `r_G <= r_I`。
现在看最优解：把 `I` 换成 `G`，会不会和最优解里其他区间冲突？
- 在 `G` 左边：`I` 已经是最优解中右端点最小的，所以左边没有别的区间。
- 在 `G` 右边：`G` 的右端点更靠左，只会更不容易冲突，原来和 `I` 不冲突的区间也不会和 `G` 冲突。

所以换成 `G` 后仍然是一个数量相同的合法解。也就是说**一定存在一个最优解包含贪心的第一选择**。
把选中的 `G` 拿掉，问题缩小成"在 `G` 右边继续选"，归纳下去，贪心每一
步都可以对应到某个最优解，最终数量等于最优。

---

## 4. 本题怎么用贪心：不要枚举区间，要边扫边判

本题区间数量是 O(n^2) 级别，不可能全枚举。但我们只需要找**右端点最早结束**的那个区间。

从左往右扫描右端点 `r`，同时维护一个集合 `S`：

```
S = { p[t] : 当前段的起点 s-1 <= t <= r-1 }
```

它的含义是：**从当前段起点开始、截止到 `r-1` 的所有前缀异或值**。

当扫描到 `p[r]` 时，只要检查 `p[r] xor k` 是否在 `S` 里：

- 在，说明存在某个 `t in [s-1, r-1]` 满足 `p[t] = p[r] xor k`，
  于是 `[t+1, r]` 是合法区间，而且 `r` 就是**当前最早的右端点**，立刻选中它！
- 不在，就把 `p[r]` 也丢进 `S`，继续往后扫。

**选中的瞬间要做两件事**：
1. `ans++`；
2. 因为新区间从 `r+1` 开始，新的段起点是 `s = r+1`，所以集合 `S` 要重置成 `{p[r]}`（即 `p[s-1]`）。

这就是 O(n) 的做法（`unordered_set` 均摊 O(1)）。

---

## 5. 旧写法错在哪：把左端点钉死在段首

旧代码内层是这样：

```cpp
for (int j = i; j <= n; ++ j)
    if ((ind[j] ^ ind[i-1]) == k) { ... }
```

它要求区间左端点 `l = i`，也就是 `p[l-1] = p[i-1]` 固定为**段起点**。
但合法的左端点**可以比段起点更靠后**：只要 `t` 落在 `[s-1, r-1]` 里就行。

### 反例详解

取 `n = 4`，`a = [1, 2, 1, 3]`，`k = 2`。

前缀异或：`p = [0, 1, 3, 2, 1]`（`p[0]=0, p[1]=1, p[2]=1^2=3, p[3]=3^1=2, p[4]=2^3=1`）。

**最优解**：选 `[2,2]` 和 `[3,4]`。
- `[2,2]`：`a[2] = 2 = k` ✔
- `[3,4]`：`a[3] xor a[4] = 1 xor 3 = 2 = k` ✔
两区间不相交，答案 **2**。

**旧写法**：`i = 1` 开始，从 `j = 1` 往后试：
- `j=1`: `p1^p0 = 1 ≠ 2`
- `j=2`: `p2^p0 = 3 ≠ 2`
- `j=3`: `p3^p0 = 2 = k` → 选中 `[1,3]`，`ans=1`，跳到 `i=4`
- `i=4`: `p4^p3 = 1 ≠ 2`，无解

最终答案 **1**，比最优少 1。**根本原因**：它没有意识到可以先跳过 `a[1]`，从 `a[2]` 起跳。

**正确写法**扫描过程（用集合）：

| r | p[r] | p[r] xor k | 集合 S 命中? | 动作 |
| --- | --- | --- | --- | --- |
| 1 | 1 | 3 | {0} 中没有 | S 加入 1 → {0,1} |
| 2 | 3 | 1 | 1 在集合里 | ans=1，S 重置为 {3} |
| 3 | 2 | 0 | {3} 中没有 | S 加入 2 → {3,2} |
| 4 | 1 | 3 | 3 在集合里 | ans=2，S 重置为 {1} |

答案 **2**，正确。

> 注意第 2 步命中时，`p[r] xor k = 1` 对应的是 `p[1]`，得到区间 `[2,2]`——
> 左端点 `l = 2`，**不等于**当时的段起点 `s = 1`。这正是旧写法做不到的。

## 6. 代码骨架

```cpp
#include <bits/stdc++.h>
using namespace std;

int main () {
    int n;
    long long k;
    scanf ("%d %lld", &n, &k);

    unordered_set<long long> S;
    S.reserve (n * 2 + 10);      // 防卡常
    S.insert (0);                // p[0]

    long long p = 0;
    int ans = 0;
    for (int i = 1; i <= n; ++ i) {
        long long x;
        scanf ("%lld", &x);
        p ^= x;                  // p 变成 p[i]
        if (S.count (p ^ k)) {   // 找到右端点为 i 的最早结束区间
            ++ ans;
            S.clear ();          // 新区间从 i+1 开始
            S.insert (p);        // S = {p[i]}
        } else {
            S.insert (p);
        }
    }
    printf ("%d\n", ans);
    return 0;
}
```

---

## 7. 容易踩的坑

1. **忘记把 `0` 放进集合**：`p[0] = 0` 对应"从第 1 个元素开始的区间"，必须能查到。
2. **`k = 0`**：完全正常，`p[r] xor 0 = p[r]`，表示找"异或和为 0 的区间"，代码无需特判。
3. **数据范围**：题目只说非负整数，稳妥用 `long long` 存前缀异或与 `k`。
4. **`unordered_set` 被卡**：洛谷可能构造哈希冲突数据，可 `reserve` + 自定义哈希或改用 `set`（O(n log n) 也能过）。
5. **输出**：记得换行，别像旧的暴力那样漏掉。
6. **复杂度**：不要写双重循环，`n` 可达 `5 * 10^5`，`O(n^2)` 必然超时。
